so the same pinned subset can run on one resident worker. It validates the
planned worker set, preserves intact pairs/order and adds setup/per-case peak
allocated/reserved memory. CUDA synchronization occurs only at case measurement
endpoints, not after every operation. Thread settings for these comparisons are
`OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, `TOKENIZERS_PARALLELISM=false`; they are
process-local settings, not host/service changes.

Initial sandbox probes could not access the driver; explicit device-access

and RTX 3060 UUID `GPU-744c1cf5-9578-6aad-95c1-7a6f1c9d11db`.
An existing idle 3090 process held about 3,852 MiB and was left untouched.
Both diagnostic workers use PyTorch **2.15.0+cu132**, CUDA **13.2**.

The existing recurrence suite passes **8/8 on each GPU**: exact eager/replay
outputs and first derivatives, 512/1024 connected compositions, checkpoint
repeats, FP64 directional derivatives, eviction/stream isolation, unsupported

or learned-flow qualification. No original numeric matrix was repeated.

## Baseline observations

Each run processes the same eight main cases plus three startup cases per
worker. Main case intervals exclude initialization/integrity/reporting/IPC gaps;
end-to-end includes setup. A single ordered baseline/profile pair per card
does not establish a general speedup or a stable warm distribution.

| Run | Main case interval sum | Main CPU seconds/case | End-to-end |
|---|---:|---:|---:|
| 3090 baseline | 12.646896 s | 1.567354 | 39.483971 s |
| 3090 host profile | 12.601372 s | 1.561993 | 39.493064 s |
| 3060 baseline | 12.384660 s | 1.535788 | 39.001648 s |
| 3060 host profile | 12.965323 s | 1.606556 | 39.851179 s |

Actual model-path host profiling overhead in this pair is **−0.36% / +4.69%**
by summed main wall intervals (3090/3060). The negative observation is run noise,
not a profiling speedup. The near-equal card times and CPU/wall intervals support
prioritizing serialized host dispatch; they do not prove every operator is
CPU-limited. Main peak allocated memory is **1,937,548,800 bytes** on both cards;
setup peak is **3,622,856,704 bytes** (reserved **4,265,607,168 bytes**).

The two-card trial completes in **35.499134 s** end-to-end, approximately
**1.112×** the 3090-only throughput for this small pack. The 3090 receives three
main cases, the 3060 five; the pair stays together. Main CPU cost is
**1.601481 seconds/case**. This includes additional startup presentations and
does not measure a steady-state 2× benefit. The original runner did not record
a separate parent main-phase wall interval; do not infer one by summing parallel
case times. That field belongs in subsequent throughput comparisons.
