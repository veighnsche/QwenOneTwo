# Reference acceptance by latent receiver behavior — v1

This replaces exact canonical reconstruction as an enforced prerequisite. The
historical `reference-recovery-v1` reports and thresholds remain diagnostics;
they cannot create `ReferenceEvidence`. No historical failure is rewritten.

## Separate construction from acceptance

A frozen, fingerprint-checked candidate reference may initialize a private live
codec and supply experimental supervised targets from an existing reviewed
release. This is not semantic acceptance or permission to run training. Native
writer supervision still requires exact reference-origin payload equality,
complete grounded evidence, candidate identities and the current admitted
snapshot. Nearby vectors do not acquire labels. Diagnostic fixtures remain
excluded from optimizer accumulation. Reason retains its documented exception:
only the separate approved Reason view may contain status/support annotations.

Semantic acceptance now means observed compatibility of a particular **reference
and receiver configuration**, not exact English reconstruction. Reports bind both
identities, reviewed release, implementation sources, profile and GPU. Changed
receiver weights require another measurement before claiming acceptance.

## Finite existing-data protocol

Run all selected development X pairs applicable to the latent receiver: categories
1–8 and 10, **180 cases / 90 pairs** in the existing release. No sampling or new
annotations. Category 9's 20 supplied-return native-reader cases are listed as
omitted because they test a different component. They remain required for future
native result-use evidence; this run cannot certify them.

| Category | Existing intervention |
|---|---|
| 1 | Negated proposition with identical evidence |
| 2 | Changed eligibility criterion/rule |
| 3 | Removed required evidence, with changed status |
| 4 | Invariance to a withheld external fact change with identical permitted inputs |
| 5 | Candidate renaming/permutation, preserving reviewed identity mapping |
| 6 | Changed candidate properties and acceptable selection set |
| 7 | Reversed rubric and direction |
| 8 | Changed numeric scale/anchors |
| 10 | Misleading supplied return withheld from receiver inputs |

Construct a fresh permitted CleanView from request semantics and exact source
facts/rules. Never import supervision, Reason, supplied returns or the human
prompt into receiver inputs. The fixed neutral Session prompt cannot carry the
answer or substitute for the latent question. Offline reference annotation
encoding is separate from invocation. Invoke actual Qev with `Session.evaluate`
on the production latent `Packet`; decode its actual heads and deliver its actual
latent result. No head overrides, gold repairs, generated gloss judge, native
teacher forcing, optimizer or gradients. Offline source encodings begin fresh;
each actual Session has one prefill and one uninterrupted causal cache.

Compare actual results to existing reviewed labels only after evaluation:

- Status must match. A non-assessed result must carry a valid bound Reason and
  must not carry a scalar or selection. This checks Reason structure/presence,
  **not the meaning of its support**.
- Noul uses the truth decision of its continuous probability: strictly above
  0.5 for true, strictly below for false. A tie fails. Preserve the original
  reviewed `p_true` and report the unmodified probability; calibration is a
  separate diagnostic, not an exact probability-1 gate.
- Choice must resolve to an actual candidate Ref in this snapshot and then to
  its exact reviewed identity, in the acceptable selection set. Never accept an
  index, invented identity or a semantically nearby alternative as that identity.
- Score must lie inside the original approved interval with **no widening**.
  Represent interval endpoints in the scalar ABI's FP32, while retaining the
  original decimal annotations. Preserve numeric/unit bytes in source inputs;
  do not round inputs, substitute values or infer absent units.
- Both cases must pass for an intervention pair to pass. Constant responses
  cannot satisfy the required proposition/rubric changes merely by being stable.
- Every successful exchange must have latent request/result types, exact snapshot
  and candidate binding, one consumption, one prefill, continuous cache and exact
  `P+B+A+H` accounting. Construction/decode failures stay in denominators.

Use the existing component thresholds for this scoped acceptance: >=90% correct
overall, >=85% per operation, >=95% status accuracy, >=90% reviewed Score agreement
and >=90% complete intervention pairs. Zero observed transport/binding/cache/
accounting violations and unchanged W/reference/receiver weights are mandatory.
These are recorded experiment criteria, not a claim that broader domain quotas
or perfect wording are essential to an MVP demonstration. Keep per-case outcomes
and correlated family/pair denominators visible.

`load_reference_evidence` now loads only this protocol, verifies hashes and
recomputes grades/denominators from the reviewed release. A boolean, a frozen
artifact, a successful exact reconstruction or a report from different receiver
weights cannot confer this acceptance.

This acceptance does **not** establish learned invocation, unforced writer
semantics, isolated-reader performance, Reason support meaning, correct native
answer use or full-flow competence. Those need their own actual behavioral tests.
A failed receiver comparison does not isolate a bad pooler from an untrained D
receiver; report that limitation rather than blaming either from this test alone.
