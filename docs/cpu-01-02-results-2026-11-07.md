## CPU-01 acceptance and measurement scope

Parent and worker process CPU time uses `process_time_ns` (including native
threads); elapsed intervals use `perf_counter_ns`. Reports separate parent plus
both worker CPU totals, setup-inclusive CPU/case, main-case CPU/case, throughput,
per-worker setup/startup/main/IPC/final-integrity phases and canonical case
measurements. Dispatch adds send/receive counts and parent CPU time. Existing
case results remain separate from measurement fields and are graded as before.
Worker ordinals label execution order; startup does not guarantee warm shapes.

Parent totals stop before final report encoding; worker totals stop before the
final send and teardown. Final report encoding/write-close is a separate journal
event. Inclusive/exclusive nested phases avoid summing child cost twice. A CPU
interval is not a count of launch overhead: it includes other host work; wall
minus CPU is not GPU compute or idle. Those two GPU fields remain null.

`--profile-host` enables worker-local Python call scopes for source/reference
encoding, reference pooling, backbone/Session/codec execution, decoding, finite
and device guards, fingerprinting and recurrence capture/copy work. Counts are
selected Python calls, **not CUDA kernel launch counts**. The recorder restores
patched methods, results and exceptions. It is intended for this single-threaded
read-only worker path, not autograd-thread attribution.

Detailed recurrence counters cover lookups/hits/misses, actual keys, evictions,
capture attempts and completed captures. The eight-entry cache policy is unchanged.
Three existing audit-copy sites report explicit requested calls/bytes and host
copy/byte-conversion intervals, retaining their original method/byte order.
These counts exclude scalar decisions, other transfers and actual bus traffic.
When detailed profiling is off, these sites only perform a recorder lookup and
the original expression; there is no new explicit device synchronization.

`--trace-cuda` implies host profiling and requests a future Torch CPU/CUDA trace
of the **first main job per worker**, exported beside the receipts. It does not
trace setup, guarantee profiler support or execute during preparation. Actual
trace/device events are needed to separate kernels, waits and transfer activity;
no such trace was collected. Trace/export cost remains in job/process totals.

## Validation and limits

- **88/88 CPU-only tests pass in 19.029 s** across recorder/aggregation,
  byte/call-order, actual cache metadata, selection, dispatch/device policy,
  provenance/Reason, eligibility, behavioral grading and accounting fixtures.
  Torch, Transformers, Safetensors, Triton and CuPy imports are blocked, including
  in spawned CPU echo workers. Tensor-shaped fixtures contain literal test bytes
  and fake metadata; they are not model outputs.
- The final targeted dispatch suite passes **11/11 in 0.746 s**, verifying the
  added send/receive/CPU fields and execution guards.
- All **310 existing final 3090 E/X receipts** pass current identity, grade and
  accounting checks. This revalidates saved observations, producing zero new
  GPU/3060 results. Full-plan case/job bindings agree with the previous plan.
- Against base commit `3907e61`, normalized AST comparison of clean encoding,
  reference fingerprinting and recurrence is identical after removing only
  instrumentation and expanding the original copy chain. Session, neural
  guards/math, backbone and actual receiver evaluator are byte-identical.
  This checks source preservation, not runtime numerical/gradient equivalence.
- An initial broad run had one AST-fixture namespace error; the fixture lacked
  its package for a relative import. The fix restores that namespace. Both the
  failed and passing logs are retained; no model failure is concealed.

Instrumentation overhead was measured separately on a **literal-byte Python
fixture**, five alternating pairs of 10,000 calls/path. Total recorded profiled
calls: 50,000. CPU time per call ranged **0.077–0.082 µs without hooks** and
**3.920–4.112 µs with hooks**. Wall samples and exact payload hash are retained.
This exposes recorder overhead only; it does not estimate model-path overhead,
GPU timing or the inactive ContextVar overhead. Future real comparisons must
measure detailed profiling/trace overhead against the same-card baseline.
